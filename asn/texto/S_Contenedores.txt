Qué es un contenedor
●    Un contenedor es un proceso ordinario del sistema operativo anfitrión que ejecuta una
     aplicación en un entorno aislado y delimitado mediante mecanismos nativos del kernel
     (como Namespaces, cgroups y políticas de seguridad).

Consideraciones de uso
    ● Duración: vinculados a la
      ejecución de una aplicación
    ● Contienen sólo elementos
      necesarios para ejecutar la
      aplicación
    ● Se deben considerar inmutables
        ○ ficheros, datos o logs deben ubicarse
          en volúmenes o servicios externos

Lanzar el primer contenedor
1.- Abrir un terminal (wsl, cmd, powershell en Windows o incluso cloud power shell en GCP)
2.- Localizar nombre del contenedor en https://hub.docker.com o en línea de comandos:
$ docker search ubuntu
2.- Lanzar shell en contenedor temporal (se elimina al finalizar)
$ docker run -it --rm ubuntu:26.04 /bin/bash                    #-it para habilitar terminal
3.- Ejecución permanente de contenedores (opción detach, -d)
$ docker run -d -it --name myserver ubuntu:26.04 # asignamos un nombre fijo
$ docker ps               # lista contenedores en ejecución
$ docker attach myserver # conectarse terminal (Ctrl+PQ para desconectar)
$ docker stop/start myserver
4.- Gestión de imágenes y contenedores disponibles                        También se puede usar el cliente
$ docker images                                                           gráfico de Docker Desktop o la
                                                                          extensión de docker en VScode
$ docker ps -a               # lista todos los contenedores               para gestionar el estado de los
                                                                          contenedores
$ docker rm myserver # borrar contenedor parado

Desarrollando sobre contenedores
● Crear una imagen del contenedor cada vez que queremos probar un
  cambio en el código es un proceso costoso
● Durante el desarrollo se suele mapear (mount, bind) una carpeta del
  host (mutable) sobre una carpeta del contenedor (inmutable)
      ○    Ejemplo: (windows powershell/cmd)
                 docker run -v c:\Users\usuario\appweb\html:/var/www/html …
      ○    Nota: La ruta en host debe ser absoluta. Se puede utilizar $(pwd) en unix/powershell, o %cd%
           (windows cmd) para referirse al directorio actual, e.g. -v $(pwd)\appweb\html

● Cuando la aplicación está desarrollada, entonces sí se puede crear la
  imagen inmutable con una copia de la aplicación.
● Es necesario publicar los puertos del contenedor en el host para acceder
  al servicio
   ○ Ejemplo
8          docker run -p 8080:80 ...

 Acceso a recursos en contenedores
 1.- Lanzar contenedor: abrir su puerto 80 y compartirle carpeta en VM docker
 $ git clone https://github.com/jrbalsas/asnwebapps.git; cd htmlsite ; tree
 $ docker run -d -p 8080:80 -v $(pwd)/html:/var/www/html \
                 --name www-server php:8-apache
 $ docker ps
                                                       ver detalles de uso del contenedor y variantes del
 2.- Programar y probar…                               contenedor en https://hub.docker.com/_/php/

 Editar contenidos en carpeta html y probar en http://localhost:8080
 3.- Comprobar logs de contenedor
 $ docker logs www-server

 4.- Acceder a contenedor en ejecución (e.g. ejecutar consola bash)
 $ docker exec -it www-server /bin/bash

 5.- Parar/arrancar/borrar contenedor
 $ docker stop/start/rm www-server

Automatización de lanzamiento de
contenedores locales
●      docker compose facilita las tareas de creación y ejecución local de contenedores
        ○ Docker lo tiene integrado en versiones modernas, e.g. $ docker compose …
●      Utiliza un fichero docker-compose.yml con detalles de despliegue
●      Ejemplo:
    services:                                              Declaración de contenedores a lanzar
        wwwserver:                                         Nombre del contenedor
           build: .                                              Cómo construir la imagen (dónde está Dockerfile)
           image: asn/phpwebapp                                  Nombre de la imagen a utilizar
           environment:                                          Variables de entorno
                PORT: 80
           ports:                                                    Puertos que se publicarán
                - "8080:80"
           volumes:
                                                                     Volúmenes/carpetas a compartir en contenedor
                - ./html:/var/www/html
 ●     Uso
       $ docker compose up -d #en versiones antiguas utilizar la herramienta docker-compose.sh
       $ docker compose ps
       $ docker compose stop/start/down

     Creación de una imagen
●     Se crean a partir de ficheros Dockerfile que definen su composición:
       ○   Imagen base (opcional :version)
       ○   Modificaciones sobre la imagen, e.g. instalación de paquetes adicionales, código de la
           aplicación, etc.
       ○   Elementos de configuración: puertos, volúmenes adicionales, entorno, etc.
       ○   Aplicación a ejecutar en el contenedor
●     Ejemplo de fichero Dockerfile
             FROM node:latest                       Imagen base
             LABEL maintainer="jrbalsas@ujaen.es"   Metadatos para registro

             WORKDIR /app                           Directorio por defecto de app del contenedor

             COPY src/package*.json ./              Fichero de configuración de proyecto node

             RUN npm install                        Descargar dependencias necesarias en contenedor
             COPY src/ ./                           Copiar fuentes proyecto

             #ENV PORT=4000                         Opcional: variable de entorno para aplicación
             EXPOSE 3000                            Metadatos (solo información): puerto accesible en contenedor

             ENTRYPOINT ["node","app.js"]           Aplicación a ejecutar (si no existe utiliza la de la imagen base)
●     Construcción de la imagen
   $ docker build -t asn/htmlsite . # utiliza Dockerfile en carpeta actual
   $ docker images asn/htmlsite               # Listar detalles de la imagen
   $ docker rmi asn/htmlsite                  # Borrar imagen

     Publicación en un registro
Pasos generales
       1.- Añadir una etiqueta a la imagen que contenga el nombre host:puerto del registro, ID
       del repositorio y nombre de imagen
       $ docker tag asn/phpwebapp host_registro:5000/ID_REPO/phpwebapp
       2.- Enviar imagen al registro (puede ser necesaria identificación previa)
       $ docker push host_registro:5000/ID_REPO/phpwebapp
       3.- Descargar imagen desde registro remoto
       $ docker pull host_registro:5000/ID_REPO/phpwebapp
Ejemplo:
    Registros en Docker hub https://hub.docker.com
      1.- Registrar usuario en Docker hub y crear repositorio público para imagen, e.g.
      phpwebapp
       2.- Identificarse en local con credenciales
             $ docker login
       3.- Etiquetar imagen y enviar
             $ docker tag asn/phpwebapp usuario/phpwebapp             Consultar detalles de imagen en
             $ docker images                                          https://hub.docker.com/u/usuario
             $ docker push usuario/phpwebapp

Publicación de un contenedor en Google
Artifact Registry
●     GCP permite lanzar contenedores desde registros públicos (docker hub) o privados
      (Google Artifact Registry)

●     Gestionar repositorio privado en Google Artifact Registry
       ○ Habilitar API de Artifact Registry en consola de Google Cloud
       ○ Crear repositorio desde consola Google Cloud, e.g. nombre: images, formato:
           docker, modo: estándar, región: us-central1                 Recomendaciones:

       ○ Autorizar cliente local docker para acceder al registro        1. Si utilizas windows es preferible
                                                                           instalar las herramientas de gcloud
            ■ requisito: instalar herramienta de gestión CLI gcloud        desde una distribución linux (e.g.
                                                                           ubuntu) en WSL2
           $ gcloud auth login
           $ gcloud auth configure-docker us-central1-docker.pkg.dev    2. Si utilizas Google Cloud Shell las
                                                                           herramientas gcloud ya están
       ○   Etiquetar imagen como zona-docker.pkg.dev/proyecto/repo/imagen instaladas
           $ docker tag asn/phpwebapp us-central1-docker.pkg.dev/mast-sec/images/phpwebapp
       ○   Enviar imagen y consultar
           $ docker push us-central1-docker.pkg.dev/mast-sec/images/phpwebapp
           $ gcloud artifacts docker images list us-central1-docker.pkg.dev/mast-sec/images/

Lanzar contenedores en Cloud Run
 ● Ventajas
       ○    Arquitectura Serverless (basada en cluster Kubernetes)
       ○    Pago por uso de recursos: pago por memoria y cpu consumida
       ○    Escalado elástico de contenedores según conexiones simultaneas (por
            defecto de 0 a 1000 contenedores)
       ○    Soporte integrado TLS, monitorización y registro
       ○    Permite desplegar desde repositorios públicos (docker hub) y privados
 ● Inconvenientes
       ○    Contenedores sin estado (i.e. se puede borrar el disco local). Necesitan
            servicios externos, e.g. db
       ○    El servicio del contenedor debe escuchar en un puerto definido por la
            variable de entorno PORT
       ○    Por cuestiones de seguridad, puede haber limitaciones extra en los permisos
            de los contenedores respecto a una ejecución local del contenedor

 Despliegue en Cloud Run




$ gcloud run deploy phpwebapp --region=us-central1 –project=mast-sec \
     --image=us-central1-docker.pkg.dev/mast-sec/images/phpwebapp \
     --max-instances=2 --memory=256Mi --allow-unauthenticated         Opciones: desde interfaz web o CLI
$ gcloud run services list –project=mast-sec
$ gcloud run services delete phpwebapp –region=us-central1      Más detalles sobre uso de CLI
